# 内容数据规范（v0.2）

## 作品文件

作品使用 UTF-8 编码的 Markdown 文件，放在 `content/works/`。文件开头的 YAML 区块是元数据，正文为小说正文或作品介绍。

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 全站唯一、稳定的英文标识，不随标题更改 |
| `title` | 是 | 作品标题 |
| `author` | 是 | 作者 ID，关联 `content/authors/` |
| `author_display` | 建议 | 发布时显示的作者名 |
| `kind` | 是 | `text` 或 `image` |
| `published` | 是 | `YYYY-MM-DD` |
| `tags` | 是 | 自由标签数组，不设固定标签库或层级 |
| `cover` | 是 | 封面路径；图像作品原则上使用处理后的第一张图 |
| `images` | 图像作品 | 图集路径列表；本阶段示例为空数组 |
| `summary` | 是 | 列表摘要 |
| `status` | 是 | `draft` 或 `published` |

作者字段和标签以稳定 ID/自由文本分别保存，避免改显示名称时破坏关联。后续 CMS 将以同一结构生成表单。

## 作者文件

作者资料放在 `content/authors/<author-id>.yml`，包含 `id`、`display_name`、`role`、`bio` 和可选的公开链接。这里的 `role` 只是内容元数据，不是安全权限证明；真正的作者权限必须由认证服务和服务端检查。

## 动态数据（尚未接入）

评论、回复、点赞、收藏、订阅邮箱、举报和审计日志不应写进公开的静态文件。后续需使用动态后端，校验身份和资源所有权，并设置限流、垃圾内容防护和管理员删除能力。

## 图片处理（尚未接入）

上传流程应在服务端或可信自动化环境生成右下角半透明水印版本，再生成缩略图。公开站点只发布水印版本；不要把原图上传到公开仓库。水印不能阻止截图或所有形式的盗用。
