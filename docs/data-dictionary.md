GX：野草莓之地 — 数据字典

版本：v1.0  
状态：现有静态数据结构梳理与未来扩展规划

1. 当前架构

网站当前使用 JavaScript 文件保存静态数据：

- `data/works.js`：作品数据。
- `data/authors.js`：作者资料。
- `app.js`：首页展示、作品交互和作者索引。
- `author.js`：独立作者主页及作者作品展示。

当前数据通过 `window.GX_WORKS` 和 `window.GX_AUTHORS` 暴露给页面使用。

2. 当前作品字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| title | string | 是 | 作品标题 |
| author | string | 是 | 作者昵称，当前用于关联作者 |
| kind | string | 是 | 作品类型，如文字、图像 |
| tags | string[] | 否 | 作品标签 |
| date | string | 是 | 当前用于展示的日期 |
| likes | number | 否 | 当前为静态点赞数字 |
| description | string | 否 | 作品简介 |
| images | string[] | 否 | 图像作品的图片地址 |

3. 当前作者字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| name | string | 是 | 作者昵称 |
| bio | string | 否 | 作者简介 |
| avatar | string | 否 | 头像地址 |
| role | string | 否 | 作者展示身份或创作类型 |

4. 已识别的问题

1. 作品通过作者昵称关联作者，昵称修改可能导致关联失效。
2. 作品没有独立且稳定的唯一 ID。
3. 点赞数目前是静态数据，不能代表真实用户互动。
4. 当前数据没有明确区分草稿、待审核和已发布作品。
5. 图片地址目前允许内嵌在数据文件中，未来需要规划独立存储方式。

5. 未来扩展规划

作者

计划增加：
- authorId：稳定且唯一的作者标识。
- accountStatus：账号状态。
- createdAt：注册时间。

昵称、简介、头像和展示身份继续保留。

作品

计划增加：

- workId：稳定且唯一的作品标识。
- authorId：关联作者的唯一标识。
- status：作品状态。
- createdAt：创建时间。
- updatedAt：最近修改时间。
- submittedAt：提交审核时间。
- reviewedAt：审核完成时间。

未来状态建议包括 draft（草稿）、pending（待审核）、published（已发布）、rejected（已退回）、withdrawn（已撤回）。

审核与权限

- 作者只能管理自己有权管理的作品。
- 作者提交作品后进入待审核状态。
- 只有审核通过的作品才公开展示。
- 站长可以审核、退回或撤回作品。
- 权限必须由后端验证，不能只依赖前端隐藏按钮。

6. 迁移原则

1. 保留当前网站可正常使用的展示逻辑。
2. 先为现有作者和作品分配稳定 ID。
3. 更新作者与作品的关联逻辑，并测试作者主页。
4. 后续引入后端与数据库时，再迁移账号、投稿和审核数据。
5. 不将静态文件中的模拟点赞数视为真实互动数据。

7. 当前阶段的完成标准

- 已记录现有作品与作者字段。
- 已明确昵称不能作为永久身份标识。
- 已规划未来的作品 ID、作者 ID 和审核状态。
- 尚未实施的字段不会被误认为已经上线的功能。
